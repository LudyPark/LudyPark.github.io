Payments

Adding four payment methods without breaking one-tip-per-ride

Problem
Four payment methods had to enter an existing tip flow without violating the one-tip-per-ride invariant.
Decision
Kept the database unique constraint as the final guard, separated idempotency from the ride reference, and handled synchronous capture and asynchronous callback completion explicitly.
Result
Four methods now run across two regions, and three defects in the shared payment path were corrected.

Payments

Handling a fare increase after authorization

Problem
A destination change could raise the final fare without securing the increase before settlement.
Decision
Preserved the original authorization and created a second hold only for the positive delta because MoMo could not increase an existing hold and the production AOF fee rate was zero.
Result
The original hold remains intact, and a destination-change increase is now either separately authorized or the change is rejected. This moves the authorization boundary from settlement time to the destination-change decision; no collection-rate improvement was measured.

Reliability

Tracing recurring pod restarts to transaction scope

Problem
A vehicle-data service restarted every three to five minutes even after its memory limit was doubled.
Decision
Used accumulated thread CPU, transaction duration, and HikariCP waits to trace the failure to reflection-based alert serialization inside a database transaction.
Result
External reporting moved outside the transaction; restarts stopped and container memory settled near 2.4 GiB.

Distributed systems

Scaling MQTT ingestion without duplicating writes

Problem
A second replica duplicated MQTT writes, while TCP commands could reach a pod that did not own the target socket.
Decision
Used MQTT shared subscriptions for inbound distribution and RabbitMQ fan-out for pod-local TCP connection ownership.
Result
The service no longer depends on a single replica for correct ingestion, without claiming end-to-end exactly-once processing.

Single-replica assumption removedinbound work distributed by broker

Engineering enablement

Centralizing review policy across ten repositories

Problem
Review workflows and prompts were copied across ten repositories and five technology stacks, so each rule change risked omissions and policy drift.
Decision
Centralized the policy, synchronized it to service repositories, and selected stack- and change-specific reviews, with dedicated SQL and migration paths.
Result

Cost and operations

Finding the workload behind an S3 API-cost spike

Problem
S3 API cost reached $138 per day, but principal-based attribution pointed to the wrong workload.
Decision
Re-aggregated CloudTrail by user agent and matched request windows with Athena execution IDs and scheduled SQL.
Result
Five unused schedules were removed and S3 API cost fell to $6 per day.

Algorithms and device data

Filtering battery state under driving load

Problem
Load-induced voltage sag could make a moving vehicle appear almost empty and distort battery-swap pricing.
Decision
Combined a causal Hampel filter using median absolute deviation with an asymmetric EMA and confirmed-stop pricing rules.
Result
Recorded-trace simulation reduced the maximum displayed drop from about 25 percentage points to about 6; this was not a production A/B measurement.

25 pp → ~6 pprecorded-trace simulation
